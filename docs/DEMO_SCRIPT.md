# 时序 ChronoFlow 功能演示视频稿（4 分 50 秒）

适用版本：本仓库当前原生 Android 端 `apps/android`。网页目前不接入训练的规划模型，因此本稿以手机录屏为主。

演示主线：**一条课程通知 → 核对成任务 → 避开课程安排时间 → 锁定与变更重排 → 记录完成反馈。**

下文“口播”可直接朗读，“操作”供录屏时照做，无需念出。时间表包含点击、阅读和短暂停顿；输入与等待可以剪辑，但应保留真实结果。

## 一、录制前准备（不计入视频时长）

### 1. 设备与功能设置

1. 安装当前包含内置模型的 APK：`apps/android/app/build/outputs/apk/debug/app-debug.apk`。
2. 用专门的演示账号进入，或在登录页点右下角 **「游客模式」**。账号、游客和工作空间在本机保存。
3. 在 **「设置 → 智能日程规划」** 中打开 **「开启本机智能规划」**。
4. 主线演示关闭可选联网 AI、**「开始采集群通知」** 和 **「自动应用明确的规则识别事项」**，保证通知先进入人工核对。
5. 每天可安排时间设为 **08:00–22:00**，时区使用当前手机时区。开启录屏和触摸位置显示，关闭无关应用的弹窗。
6. 若使用游客空间中已有数据，不要清除整个应用；优先改用独立的本机演示账号。

**录前必须试一次真实模型调用：**打开飞行模式，并确认 Wi-Fi、移动数据均关闭，点「今天 → 生成智能计划」。只有实际出现 **「当前计划：本机智能规划」** 和任务的 **P50 / P80 / P95**，才录制离线模型片段。当前仓库记录已通过构建及相关检查，但真实手机飞行模式推理仍需设备验收；本文是录制方案，不代表已实机验证。

### 2. 准备统一的演示数据

“明天”“后天”均以实际录制日期为准。若在 2026 年 10 月 18 日录制，分别是 10 月 19 日和 10 月 20 日；换日录制须重新核对。

| 数据 | 具体内容 | 准备方式 |
|---|---|---|
| 预置任务 | 高等数学复习；分组「高等数学」；类型「复习」；难度 3；预计 60 分钟；后天 22:00 截止；允许拆分 | 录制前在「任务 → 新建任务」创建，点「保存并排程」 |
| 首条通知 | 群名：计算机网络课程群；正文见下方 | 录制中粘贴 |
| 固定课程 | 计算机网络课程；明天 09:00–10:00 | 录制中在「日历 → 固定日程」添加 |
| 延期通知 | 使用与首条通知完全一致的群名；正文见下方 | 录制中粘贴 |
| 完成记录 | 高等数学复习；实际用时 100 分钟 | 录制末段演示，字幕标注「模拟完成记录」 |

首条通知，提前放入可随时粘贴的备忘录：

```text
实验三明天18:00前提交，预计2小时
```

延期通知：

```text
实验三延期，改到后天18:00提交
```

课程时段可按彩排调整：若任务全排在今天，明天的课程虽然被避开，画面对比却不明显。可将课程改到彩排中某个**尚未开始的任务时间块**，占用其中 1 小时，再演示重新安排。以设备实际计划为准，不预设模型一定选择几点。

### 3. 彩排与素材

- 按完整流程走一次，记下任务实际排在哪一天，录制时直接切换对应日期。
- 彩排后使用另一演示账号，或取消彩排事项并重新准备；不要把重复的「实验三」留在同一课程群下。
- 首次模型初始化在正式录制前完成。录到等待较长时，可剪去中间等待，并标注「等待已剪辑」。
- 提前截取锁定时间块的任务名、日期与起止时间，用于后面的前后对比。
- 主线不依赖真实群消息、Canvas Token 或 LLM 密钥。若替换为这些功能，先完成真实联调，再决定录制内容。

## 三、逐段操作与口播

### 01｜00:00–00:20：用一个真实场景开场

**操作**

1. 从「今天」首页开始，停留 3 秒，展示产品名与智能规划卡片。
2. 简短展示底部「发现、任务、日历」入口，最后停在「发现」。
3. 登录和密码输入提前完成，无需放入成片。

**口播**

> 课程作业、群通知和临时调整，经常分散在不同地方。时序 ChronoFlow 把这些信息整理成任务，再结合课表和截止时间安排计划。接下来，用一次作业通知，演示从信息进入到完成反馈的整个过程。

**字幕**：时序 ChronoFlow｜从课程信息到可执行计划

### 02｜00:20–01:05：把通知核对成任务

**操作**

1. 点 **「发现 → 录入通知」**。
2. 「群名（用于关联已有事项）」填 **计算机网络课程群**。
3. 粘贴 **实验三明天18:00前提交，预计2小时**，点 **「识别」**。
4. 在待确认卡片上停留，展示原文、动作、截止及需要核对的提示。
5. 点 **「核对并确认」**：检查动作为「创建任务」，名称为「实验三」，截止为明天 18:00，预计耗时为 120 分钟。任何字段不正确，先在该页修正。
6. 点 **「确认应用」**，切到 **「任务」**，展示新出现的「实验三」。

**口播**

> 我先粘贴一条课程通知：实验三明天十八点前提交，预计两小时。系统提取出任务名称、截止时间和预计耗时，先放进待确认列表。这里使用的是本地规则识别。核对无误后点击确认，通知才成为正式任务，并进入排程流程。识别不准确的字段，也可以在这一步修正。

**字幕**：通知 → 待确认 → 正式任务

**拍摄重点**：输入原文和确认字段各停留约 2 秒；粘贴时可剪去键盘展开过程。

### 03｜01:05–01:40：把课程作为固定约束

**操作**

1. 点 **「日历 → 固定日程」**。
2. 在「课程、会议或考试」填 **计算机网络课程**。
3. 点「开始」选择明天 **09:00**，点「结束」选择明天 **10:00**，再点 **「保存」**。
4. 切到课程所在日期，展示固定日程卡片；再展示任务实际所在日期的专注时间。
5. 若彩排时采用了其他课程时段，这里使用同一时段。

**口播**

> 接着加入一节固定课程。课程是已经确定的时间，任务需要围绕这些约束安排。保存后，在日历中可以看到固定课程和任务专注时间。检查它们的起止时间，任务块应当避开课程；如果当天空间不足，就需要在截止之前寻找其他可用时段。

**字幕**：固定课程参与排程｜任务安排避开占用时间

**拍摄重点**：起止时间比快速滚动更有说服力；两类卡片各保留清楚的时间标签。

### 04｜01:40–02:25：展示内置模型在手机离线生成计划

**操作**

1. 录下打开飞行模式的动作，确认 **Wi-Fi 和移动数据也关闭**。
2. 回到 **「今天」**，点 **「生成智能计划」**。
3. 等待计算完成。保留一次点击和完成结果，等待过长可剪辑。
4. 特写 **「当前计划：本机智能规划」** 以及「实验三」的 **P50 / P80 / P95 分钟**。
5. 切到 **「日历」**，展示生成后的任务时间块。后续主线可继续保持断网。

**口播**

> 现在关闭网络，点击生成智能计划。规划模型已经内置在手机里，会结合任务、固定课程和已有执行反馈安排时间。生成成功后，首页会明确显示本机智能规划，并列出任务耗时的 P50、P80 和 P95 预测。不同分位数反映耗时的不确定性；这里的数值是预测，实际仍要以执行情况为准。

**字幕**：手机本机推理｜无需规划服务器｜耗时存在不确定性

**拍摄重点**：必须拍到这次断网之后重新生成的结果；具体数值按设备实际输出展示，不预写分钟数或推理速度。

### 05｜02:25–03:00：保留用户锁定的时间

**操作**

1. 在 **「日历」** 找到「实验三」一个尚未开始的专注时间块，点 **「锁定时间」**。
2. 展示 **「专注时间 · 已锁定」**，记下该块日期与起止时间。
3. 到 **「任务」**，点「高等数学复习」的 **「编辑」**。
4. 将 **「预计总耗时（分钟）」和「剩余耗时（分钟）」都改为 120**，点 **「保存并排程」**。
5. 返回原日期，展示「实验三」锁定块的起止时间。可用左右对照小图标注修改前后。

**口播**

> 有些时间我已经决定好了，可以直接锁定。现在把复习任务从一小时增加到两小时，重新安排后，再看刚才锁定的时间块：它的起止时间保持不变。这样，任务发生变化时，我已经确定的安排也能保留下来。

**字幕**：任务工作量变化 → 重新排程｜锁定时间保持不变

**拍摄重点**：以锁定块前后时间一致为证据，不要求其他任务一定出现明显位移。

### 06｜03:00–03:50：延期更新同一任务，并保留来源

**操作**

1. 点 **「发现 → 录入通知」**，群名仍填 **计算机网络课程群**。
2. 粘贴 **实验三延期，改到后天18:00提交**，点 **「识别」**。
3. 点 **「核对并确认」**，检查动作为 **「修改任务」**，目标是已有的 **「实验三 · 计算机网络课程群」**。
4. 核对截止为后天 18:00；如未自动匹配，在 **「选择对应的已有事项」** 中选择原任务。新预计耗时保持空白，即保持原值。
5. 点 **「确认应用」**，到 **「任务」** 检查「实验三」截止更新，而且没有新增第二个「实验三」。
6. 点该任务的 **「来源」**，展示原始通知和延期通知，最后点 **「关闭」**。

**口播**

> 接下来，老师通知实验三延期到后天十八点。我用同一个课程群录入这条消息，系统会尝试关联已有任务。确认页中可以核对修改动作、目标和新截止时间。应用后，原任务的截止更新，不会再新增一份相同作业。点击来源，还能查看最初通知和这次延期记录，知道每次变化来自哪里。

**字幕**：延期通知 → 核对已有任务 → 更新截止｜保留原始来源

**拍摄重点**：任务更新和来源记录是这一段的主要结果。截止放宽后，计划允许保持原样，无需强求时间块后移。

### 07｜03:50–04:30：记录完成与真实用时

**操作**

1. 在 **「日历」** 短暂展示时间块下方的 **「完成时段 / 跳过 / 延后」** 按钮。
2. 到 **「任务」**，点「高等数学复习」左侧圆圈 **「标记完成」**。
3. 打开上方 **「显示已完成 / 已取消」**，找到刚完成的任务。
4. 点 **「记录实际用时」**，在 **「实际用时（分钟，可选）」** 中填 **100**，点 **「保存并排程」**。
5. 展示任务上的 **「实际用时 100 分钟」** 和 **「已完成」**。

**口播**

> 执行之后，还可以留下反馈。日历支持记录完成时段、跳过和延后；整个任务做完后，也可以标记完成，并补充实际用时。这里用一条模拟完成记录演示：复习任务完成，实际用了 一百分钟。这些记录会作为后续个性化规划的输入，帮助调整耗时和时段判断。

**字幕**：模拟完成记录｜实际用时反馈 → 后续个性化规划

**拍摄重点**：完成记录用于说明交互；一次记录不代表模型已学会用户习惯，也不要求预测立刻发生明显变化。

### 08｜04:30–04:50：回到完整闭环

**操作**

1. 回到 **「今天」**；需要刷新时点 **「生成智能计划」**，等待结束后留 3 秒稳定画面。
2. 叠加闭环字幕和产品名，结束录制。

**口播**

> 这就是时序的使用流程：把信息核对成任务，结合课程生成计划，在变化时重新安排，再用执行反馈持续调整。核心规划在手机本地完成，让每一天都能看到清楚的下一步。

**字幕**：信息 → 确认 → 规划 → 调整 → 反馈

## 四、可替换镜头：展示 Canvas（保持总长 4 分 50 秒）

如果已经完成真实学校 Canvas 联调，可用下面的 **20 秒版本替换 00:00–00:20 开场**。从 00:20 起仍按主稿手动录入「实验三」，不影响后面的延期演示。

**录前条件**：在同一演示账号下连接 Canvas，准备一条无敏感信息、确实同步得到的待确认作业；选择与「实验三」不同的任务。录制前定位好页面，不在镜头内填写 Token。

**操作**：展示「设置 → Canvas 课程平台」的连接状态 → 切「发现」，展示来源为 Canvas 的待确认作业 → 最后停在「发现」，接回主稿。此片段只展示已同步结果，无需在 20 秒内等待新一轮同步。

**替换口播**

> 这是时序 ChronoFlow。除了手动创建任务，它还可以从学校 Canvas 同步课程信息。这里是一条已经同步的作业，先进入发现页等待核对。接下来，我用一条课程通知演示完整的规划流程。

**字幕**：真实 Canvas 同步结果｜新增与变更先核对

若未完成真实学校联调，使用主稿开场；不以手动粘贴的通知充当 Canvas 或微信/QQ 自动采集结果。

## 五、录制节奏与异常处理

### 成片节奏

- 建议竖屏录制 1080 × 1920，30 fps；若最终要横屏展示，可将手机画面居中，旁边放当前步骤和关键字幕。
- 口播按每分钟约 200–230 个中文字彩排，给点击和结果阅读留出时间。
- 每个关键结果至少留 2–3 秒：通知字段、计划来源、耗时预测、锁定时间、更新截止、来源记录、实际用时。
- 剪掉长输入、日期选择与等待的冗余过程，保留按钮点击和结果。实际生成较慢时标注「等待已剪辑」。
- 超时优先压缩页面切换和键盘操作，保留“先确认”“本机计划来源”“锁定前后时间”“延期更新原任务”四个证据镜头。
- 演示文案和来源内容使用测试数据，账号密码、Token、API Key 不进入画面。

### 遇到异常时怎么处理

| 情况 | 处理方式 |
|---|---|
| 显示「离线基础排程」或「模型规划未完成，原计划保留」 | 暂停录制，先解决模型运行问题；不能把基础计划称为内置模型结果 |
| 通知识别字段不准确 | 在「核对并确认」中修正，保留人工核对这一步 |
| 延期关联不到原任务 | 检查群名完全一致、原任务仍在进行中；手动选择已有目标 |
| 延期不改变截止 | 检查任务的「锁定截止时间」是否开启；它与日历的「锁定时间」是两个不同设置 |
| 任务和固定课程没有出现在同一天 | 切换到实际日期；若需要更明显的避让对比，录前按真实任务时间调整课程时段 |
| 反馈后预测没有明显变化 | 正常展示记录成功即可；不要宣称一次反馈就能显著改善结果 |
| 时间不足、出现无法排完的提示 | 如实展示约束或调整演示工作量，不把缺口描述成已经安排完成 |

## 六、成片导出前核对

- [ ] 总时长在 4–5 分钟，目标 4:50。
- [ ] 通知识别与模型规划的名称、作用讲清楚：本地规则负责本段文本识别，内置模型负责智能规划。
- [ ] 飞行模式下实际重新生成成功，计划来源明确为本机智能规划。
- [ ] 固定课程与任务时间无重叠，锁定块前后日期和起止时间一致。
- [ ] 延期修改的是同一任务，来源中保留两次通知。
- [ ] 模拟完成记录有标注，实际用时可见。
- [ ] 未将可选联网 AI、Canvas 同步或通知采集描述为无需网络的能力。
- [ ] 片中没有未经验证的提效百分比、实时性承诺或保证按期完成的说法。
