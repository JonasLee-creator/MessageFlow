# Android 内置模型与规划设计

## 运行结构

ModelPlannerClient 将当前账号的任务、课表、锁定计划和历史反馈传入 EmbeddedModelRuntime。后台线程调用内置 Python 的 deployment.android.run，复用特征编码、在线校准与 风险感知滚动规划器。ONNX Runtime Android 在 CPU 上执行冻结网络，规划调用不经过 HTTP。

## 模型与依赖

- ONNX：chronoflow_predictor.onnx，1,375,015 字节。
- 模型版本：0.1.0；特征契约与校验清单见 model 附件。
- 运行库：Chaquopy 17.1.0、Python 3.12、ONNX Runtime Android 1.23.2。
- 手机运行库架构：arm64-v8a、x86_64。
- 构建环境：JDK 21、Android SDK 35、Build Tools 35.0.0、Python 3.12。
- 构建任务：:app:testDebugUnitTest、:app:assembleDebug。

构建按白名单复制生产模块与模型产物，训练数据、PyTorch 检查点及服务端密钥不进入 APK。初始化核验 SHA256，特征维度不符、非有限输出或约束冲突均返回明确错误。2026-10-18 构建记录中 Debug APK 大小约 100.35 MiB，该大小包含模型及运行库。

## 规划契约

规划窗口为未来 14 天，最多 30 项活动任务，30 分钟槽，默认每日容量 360 分钟。手机通过 settings.workloadPolicy=confirmed 启用确认工时模式。预算对每项任务整体向上取整：60 分钟对应两个槽，45 分钟对应两个槽；模型分位数不自动追加预算。先扣锁定与正在执行的承诺，再分配剩余预算。受保护承诺超出预算时提示核对；截止前容量不足时显示缺口。

研究回放使用独立的模型预算模式，既有研究结果不等同于手机确认工时模式的收益。

## 数据与失败处理

每次调用按当前账号重建历史，不在全局解释器中缓存个人状态。任务、课表和反馈按身份加密保存；通知采集与联网文本分析分别授权。手动生成失败保留原计划，自动重排失败保存业务变更并标记基础排程。页面明确区分本机智能规划与基础排程。

## 设备验收协议

1. 添加两项任务和固定课程，关闭可选文本分析与通知入口。
2. 飞行模式生成计划，检查模型来源标识、分位数和课程避让。
3. 锁定时间块后新增任务重排，检查起止时间不变。
4. 记录完成、跳过、延后与实际用时，检查反馈和任务状态分别保存。
5. 强制停止并重启，再切换账号，检查恢复与身份隔离。
6. 构造无空档或预算冲突，检查错误提示与原计划保留。

设备性能分别计量模型冷启动、稳定推理和完整规划。测试记录包含设备、系统、应用版本、任务规模、占用区间、耗时与内存。JVM 单元测试验证工程逻辑，不能替代真实设备的推理和性能记录。
