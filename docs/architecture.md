# V1 架构与约束

> 此页保留旧服务端架构。当前原生手机本地版见 [ANDROID_LOCAL.md](ANDROID_LOCAL.md)，主工程为 `apps/android`。

## 核心对象

`RawInformation → AIAction → Task / Event → ScheduleBlock`

原始消息是不可变的来源修订记录；不会用新的通知正文覆盖旧记录。任务代表要完成的工作，固定日程占用时间，排程块代表系统分配给任务的时间。每次重排单独生成版本和快照。

数据库：users、connectors、courses、raw_information、extraction_results、tasks、task_sources、events、schedule_blocks、schedule_versions。

## 原始信息状态

```text
queued → processing → processed / ignored / needs_confirmation
                    ↘ failed → 用户重试 → queued
needs_confirmation → 接受 → processed
                   → 拒绝 → ignored
```

V1 在摄取请求内执行识别，通过数据库 savepoint 隔离失败；保留失败 raw。未使用 Redis 或分布式队列。通知上传可能等待模型最多 45 秒，客户端相应使用较长超时与稳定消息 ID 保证重试去重。

Canvas 使用后台轮询循环；同步过程与 HTTP 修改共用异步锁。当前是单 Uvicorn 进程架构，必须先引入数据库级用户锁/可靠任务队列才能扩展多进程。

## 识别与合并

- Canvas Assignment 使用确定性映射，外部 ID 包含连接器和课程，保存不同更新时间修订；拒绝旧版本回写。
- Canvas Announcement、微信、手工文本进入配置的模型。
- 模型只看到当前用户的有限候选集：最多 30 项活跃任务、40 项日程。匹配上下文优先考虑课程和标题，不使用向量数据库。
- 对完全相同标题与课程的新建提议，转为“确认是否合并”而非直接重复建任务。
- 自然语言更新时间缺少目标时保留待确认，不降级为创建。
- 所有取消动作、低于 0.85 置信度、显式不确定结果都需要用户确认。
- 对跨用户、已完成、已取消对象的更新或取消会拒绝。
- 日期和耗时锁定由后端强制执行；用户手动编辑任务本身可以改变这些值。
- 没有 AI 密钥时，本地规则只支持有限中文任务关键词、简单日期、已有日程取消；它不是完整语言模型，也不能可靠处理复杂复合通知。
- V1 每条消息最多一个 Action；一条通知含多个任务时需拆开录入。

## 时间与排程

所有 API 时间必须带时区，数据库统一 UTC，用户默认时区 Asia/Shanghai，界面显示手机本地时区。V1 尚无时区偏好编辑界面。

- 未来 14 天，用户时区每天 08:00–23:00，以 30 分钟为一个 slot。
- 任务耗时向上取整到 slot；截止约束检查 **slot 结束时间**，避免最后一段跨过 deadline。
- 固定日程、未来锁定块、已经开始的块占用时间，不能再次安排。
- 任务剩余工作量扣除未来锁定/进行中块的剩余分钟，避免重复分配。
- 不可拆分任务只枚举连续时间窗；已锁定块不足以覆盖增大的不可拆分任务时，提示先解锁。
- 优先级与提前安排进入目标函数，额外惩罚碎片段。
- 完成/取消任务删除其未来计划，保留已经结束的历史块。
- INFEASIBLE 或求解超时未得到可行解时，不伪造安排：移除失效的未锁定未来计划，保留锁定块并返回风险。
- 版本快照用于审计与展示，尚无“一键回滚”功能。

无 deadline 的任务按 14 天窗口安排，任务估时默认 60 分钟，均可编辑。系统不会仅因一个时间块过去就把任务自动标为完成。

## Android

Flutter 用 MethodChannel 调用 Kotlin 设置、系统通知权限、重试和日历导出。Kotlin 仅监听微信包名；通知访问默认关闭，同时要求明确群名白名单和关键词匹配。过滤发生在本机，队列保存前加密，令牌通过 Android Keystore 的 AES-GCM 密钥加密。

队列上限 500 条/7 天，WorkManager 在联网时上传，成功后删除。关闭采集、退出登录、切换服务器或修改白名单会清空队列。已经在网络中发出的请求无法撤回。

App 不读取微信数据库，不读取历史消息。微信显示通知的格式差异会影响群名匹配，用户可手动粘贴通知补充。

## 部署边界

JWT、用户隔离、密码 PBKDF2、服务端 Canvas 令牌加密和 HTTPS 正式包策略已写入代码。公开部署前仍需配置 TLS、访问限流、备份、日志/监控、密钥轮换和具体学校 Canvas 访问限制，并完成实机验证；这些不是当前已经完成的上线验收。

Canvas URL 限制 HTTPS 公网地址，拒绝本地地址、跨源分页、重定向。生产后端还应限制出站网络与学校域名列表。
