# 安装完成后的验收

以下步骤是后续验收计划，本次尚未实机执行。

1. 启动后端，模拟器安装 debug APK，检查初始界面明确显示“界面示例”。
2. 在「连接」注册账户；示例应消失，账户任务应为空。
3. 新建一项未来三天截止、180 分钟的任务“实验三”，课程填“计算机网络”。检查日历生成总计至少 180 分钟且不越过截止的计划。
4. 添加一节固定课程，确认任务块避开课程时间。
5. 在日历锁定一段时间，点击重排；锁定段的 ID/起止时间不变，总工作量没有重复增加。
6. 在「发现」输入课程“计算机网络”、通知“实验三延期到下周一提交”。无模型时必须标为“本地规则（非 AI）”并待确认。核对日期和目标后确认，任务数量不增加，来源增至一条，排程版本递增。
7. 输入“实验三取消，不用交了”，确认后任务标为取消、未来计划消失。
8. 输入“晚上有人吃饭吗”，本地规则将其忽略，不产生任务。
9. 新建 8 小时任务且截止只有 1 小时；确认显示无法排程风险，没有越过 deadline 强行安排。
10. 使用第二个账户登录，确认看不到前一个账户的任务、来源、版本或连接器。
11. Canvas 连接真实学校地址及令牌，同步一项作业；再次同步相同修订不重复创建。修改 Canvas 截止时间后再次同步，应保留同一任务 ID 并增加来源修订。
12. 真机开启通知权限，仅填写测试课程群名称；普通私聊和未在白名单的群不应进入收件箱。白名单课程群作业通知应进入后端。断网后通知留在队列，恢复联网后上传。
13. 关闭采集后确认本地队列清空；再次收到课程通知不上传。退出账户后也不上传。
14. 点击单个时间段的“添加到系统日历”，检查系统确认页字段。取消系统保存应不产生系统日历条目。
15. 测试窄屏、大字体、键盘弹出、Android 8 / 13 / 15、后台杀进程、屏幕旋转、令牌过期、不可达后端和模型异常。

比较计划变更时使用 App 内日历。系统日历的手工导出记录不会被自动更新。
