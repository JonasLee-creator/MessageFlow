# 时序 · ChronoFlow Web

个人时间管理工作台，包含今天、发现、任务、日历、复盘和设置六个页面。使用 HTML / CSS / JavaScript，无第三方依赖或构建步骤。

## 本地运行

在 `apps/web` 目录执行：

```powershell
node server.mjs
```

打开 http://127.0.0.1:4173/ 。可通过 `PORT` 环境变量改变端口。服务器只监听本机。

## 使用流程

- 默认进入登录页，填写用户名和密码；没有账号时可切换注册，填写用户名、密码与确认密码后进入工作台。
- 登录页右下角提供“游客模式”，无需注册即可进入功能区。工作台右上角可退出登录或返回登录页。
- 设置页支持官方接口与用户接口。官方密钥由服务端环境变量提供，用户接口填写自己的地址、模型和密钥；保存后可测试连接。
- 今天、发现、任务、日历、复盘、设置六页；适配桌面和窄屏。
- 通知核对，延期更新、新增任务与新增日程；修改需要确认。
- 手动粘贴通知，简单规则识别日期与耗时，结果均待确认。
- 也可使用已配置的 AI 接口识别多事项；模型结果仍需确认，取消和无法明确关联的事项由用户手动处理。
- 创建和编辑任务、课程筛选、搜索、完成并记录实际耗时。
- 日 / 周日历、周切换、锁定时间块；桌面拖动后锁定，校验冲突与截止。
- 30 分钟粒度、未来 14 天的简单排程；保留锁定和已开始安排，显示缺口。
- 每日可用时间、JSON 导出、清空工作空间。
- 使用 `localStorage` 保存当前浏览器内的数据，刷新后保留。

## 数据与运行方式

新工作空间为空，用户自行录入任务和通知。已有浏览器记录继续保留，刷新后可读取。数据保存在当前浏览器中，请勿在工作空间保存 API 密钥等凭据。

账号保存在当前浏览器，用户名不区分大小写；注册支持 2–24 个字的用户名和 8–128 位密码。密码通过 Web Crypto 使用随机盐和 PBKDF2-SHA256 派生，只保存校验值，不保存明文密码。账号流程需要 HTTPS 或 localhost / 127.0.0.1 的安全上下文。

登录状态使用当前标签页的 `sessionStorage`。每个账号使用独立的工作空间存储键，游客继续使用原有浏览器工作空间，因此之前保存的任务不会因新增登录页被删除或转移到注册账号。退出登录不删除任务；禁止存储时游客仍可在当前页面进入功能区，刷新后需重新进入。

这里的账号校验与页面入口都在浏览器内执行，不提供服务端身份认证、跨设备登录或云同步，也不能作为服务端数据的访问控制。正式接入远程用户数据时，应改用服务端账号与会话，并在每个数据接口校验权限。

排程以 30 分钟为单位，检查未来 14 天的可用时间，避开固定日程、锁定块和已开始的安排，并报告时间缺口。采用启发式算法，不保证全局最优。日期以浏览器时区显示；相对日期以录入当日为基准。手动提取产生新增任务提议，修改、取消和多事项通过任务编辑完成。

浏览器清除数据或切换站点会使用新的本地记录。JSON 导出供留存，当前不提供导入。网页使用同目录的 Node.js AI 网关，不调用旧后端、不读取手机通知，也不连接远程账号服务、Canvas 或浏览器推送。AI 网关通过配置连接兼容 Chat Completions 的模型服务。

## AI 配置与部署

参见 [API.md](API.md)。比赛阶段使用 `CHRONOFLOW_STAGE=competition`，开发者在服务端 `.env` 配置官方密钥、模型与体验码；正式使用切换为 `production`，服务端强制要求用户自备接口。用户密钥仅保存在当前标签页会话中，退出登录时清除，不进入任务导出文件。

将 `.env.example` 复制为 `.env`，填入配置后执行 `npm start`，需要 Node.js 20.6 或以上版本。不配置官方密钥也可使用用户接口与本地规则。AI 功能需要运行 Node.js 网关，单独部署 `dist/` 静态文件不会提供 AI 接口。

## 检查

```powershell
npm run check
```

包含 JavaScript 语法、游客入口、账号注册和密码校验、会话恢复与退出、不同工作空间的数据隔离、新工作空间为空、排程不冲突、截止约束、锁定保留、工作量不重复、缺口和日期解析检查，以及 API 模式隔离、正式环境关闭官方接口、体验码与额度校验。检查不连接网络或真实服务。
