## 3. 各数据文件里有什么

每行一个 JSON 对象。

开发集和金标准包含 `gold`。测试输入只有这些字段：`id`、`split`、`source`、`reference_time`、`timezone`、`text`、`context`。

`context.candidate_tasks` 里同时放了任务和日程：

- ID 以 `task-` 开头：放进 `LocalState.tasks`，状态为 `ACTIVE`
- ID 以 `event-` 开头：放进 `LocalState.events`

如果全部放进 tasks，修改和取消日程时目标校验会失败。

构造 `Incoming` 时：

- `content` = `text`
- `receivedAt` = `reference_time` 解析成的时刻
- `group` = `context.group`
- `source`：`wechat` → `Source.WECHAT`，`qq` → `Source.QQ`，`canvas` → `Source.CANVAS`，`manual` → `Source.MANUAL`
- `Preferences.zone` 固定为 `Asia/Shanghai`。不要用电脑当前时区

`gold.items` 的动作只有：`CREATE_TASK`、`UPDATE_TASK`、`CANCEL_TASK`、`CREATE_EVENT`、`UPDATE_EVENT`、`CANCEL_EVENT`、`IGNORE`。

开发集 400 条：新建任务 90，延期/修改/取消 70，日程 60，多事项 50，歧义 50，无关 50，困难样本 30。来源为微信 180、QQ 120、Canvas 60、手工 40。

测试集 100 条：新建 25，修改或取消 15，日程 15，多事项 15，模糊 15，无关 15。来源为微信 45、QQ 30、Canvas 15、手工 10。测试集没有单独的困难样本桶。

## 4. 同学开工前必须补上的程序

现有 App 没有三组实验开关。`LocalRepository.smartIngest` 在 DeepSeek 成功后，仍会进入 `LocalEngine.ingestAnalyzed`，而那里总会调用 `UncertaintyEngine.assess`。`DeepSeekClient.parseProposals` 还会提前丢掉不在原文中的证据，并丢掉不在候选列表中的 `target_id`。因此现在这条链路既不是 DeepSeek-only，也不能逐项关掉安全检查。

同学要加一个只用于实验的批量入口，默认产品行为先保持不动。Key 从环境变量 `DEEPSEEK_API_KEY` 读取，不写入结果文件，不提交 Git。

### 4.1 三组系统

三组使用同一份测试输入、同一份候选事项、同一个 `reference_time`。

| 系统名 | 行为 |
|---|---|
| `rule-only` | 只调用 `LocalParser.parse`。不访问网络 |
| `deepseek-only` | 同一次 Prompt 的原始 JSON。只检查能不能解析成约定字段。保留模型给出的证据和 `target_id`，即使证据不在原文里、目标不在候选列表里。不调用 `UncertaintyEngine`。不自动执行 |
| `full-system` | 同一份原始 JSON，再经过证据校验、目标校验、`UncertaintyEngine`。追问最多 2 条。只有 `autoSafe == true` 记为自动执行 |

DeepSeek 的原始响应要落盘。`deepseek-only`、`full-system` 和下面的安全消融都从这份原始响应派生，不要为每一列重新请求。这样消融比较的是后处理，而不是模型当天的随机差异。

`rule-only` 不使用这些响应。

### 4.2 安全机制消融

在同一份原始响应上依次打开开关：

| 配置名 | 原文证据校验 | 目标必须在候选列表 | 字段阈值 | 最多两次追问 |
|---|---|---|---|---|
| `deepseek-base` | 关 | 关 | 关 | 关 |
| `plus-evidence` | 开 | 关 | 关 | 关 |
| `plus-target` | 开 | 开 | 关 | 关 |
| `full-system` | 开 | 开 | 开 | 开 |

证据校验：证据必须是 `text` 的连续子串，否则该字段不能支持自动执行。目标校验：`UPDATE_*` / `CANCEL_*` 的 `target_id` 必须存在于对应的 tasks 或 events。字段阈值和两次追问以 `UncertaintyEngine` 现有实现为准：动作 0.65、标题 0.65、时间 0.70、目标 0.70、证据 0.55，综合分至少 0.82，且仅新建动作可以 `autoSafe`。

### 4.3 请求记录

`DeepSeekClient.request` 现在只返回正文，丢掉了用量。实验版每次调用要额外记下：

- 实际模型 ID（响应里的 `model`，不要只写配置默认值 `deepseek-flash`）
- `usage.prompt_tokens`、`usage.completion_tokens`
- HTTP 状态
- 请求耗时毫秒
- 是否重试
- 是否回退到 `LocalParser`

温度保持 0.1。封闭测试上，DeepSeek 原始请求重复 3 次，分别存为 run 1、2、3。主表用 run 1。另外报告三次动作是否一致的比例。

API 失败时，`full-system` 回退到规则结果，`fallback_used` 为 true，程序不能中断整批。

## 6. 预测文件格式

每条样本、每个系统、每一轮一行，放在 `evaluation/experiments/<系统名>/predictions.jsonl`。

```json
{
  "sample_id": "test-0001",
  "system": "full-system",
  "run": 1,
  "model": "deepseek-flash",
  "prediction": {
    "items": [
      {
        "action": "CREATE_TASK",
        "title": "实验一",
        "target_id": null,
        "deadline": "2026-09-11T10:00:00Z",
        "start": null,
        "end": null,
        "minutes": 60,
        "evidence": ["实验一"],
        "questions": []
      }
    ],
    "should_ignore": false
  },
  "latency_ms": 1350,
  "prompt_tokens": 820,
  "completion_tokens": 210,
  "http_status": 200,
  "retried": false,
  "api_error": null,
  "fallback_used": false,
  "auto_apply": false
}
```

`rule-only` 的模型字段为 null，Token 为 0，`http_status` 为 null。时间可以是 UTC 或 `+08:00`，评分时都解析成同一时刻再比较，不要比较字符串。

## 7. 指标

主表用封闭测试 run 1。

| 指标 | 算法 |
|---|---|
| 动作 Macro-F1 | 只对金标准或预测里实际出现过的动作算 F1，再平均。没有出现的动作不进入分母。对齐分两步：先按动作加去空白标题贪心匹配，剩下的再只按动作匹配。对不上的金标准算漏报，对不上的预测算误报 |
| 标题准确率 | 上面对齐成功的配对里，标题去掉全部空白后相同的比例 |
| 时间准确率 | 任务比 `deadline`；日程比 `start` 和 `end`。比较前把秒和微秒截成 0。取消动作两边都为空算正确 |
| 目标匹配准确率 | 只统计 `UPDATE_*` 和 `CANCEL_*`，`target_id` 相同算正确 |
| 多事项拆分 F1 | 只统计金标准至少两条 item 的样本 |
| 无关信息误报率 | `should_ignore == true` 的样本里，预测出任何非 `IGNORE` 动作的比例 |
| 追问召回率 | 金标准 `requires_question == true` 的样本里，预测 `questions` 非空的比例 |
| 幻觉率 | 标题既不在原文也不在候选标题中，或任一 evidence 不是原文连续子串的样本比例 |
| 自动执行覆盖率 | `auto_apply == true` 的样本比例 |
| 错误自动执行率 | 自动执行样本中，动作、标题、时间或目标与金标准不一致的比例 |
| P50 / P95 延迟 | `latency_ms` |
| 单条平均成本 | 平均 Token 数；单价按同学账户账单填写，不要估一个数写死 |
| 降级成功率 | `api_error` 非空时，`fallback_used == true` 且结果与同一样本的 `rule-only` 相同的比例 |

安全消融表至少报告错误自动执行率，并保留 P95 延迟和平均 Token，不要只留最好看的一列。
